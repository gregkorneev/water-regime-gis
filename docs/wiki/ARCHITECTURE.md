# Architecture

## Общий принцип

Проект разворачивается в QGIS-first личный сервис. Основной пользовательский интерфейс теперь — установленный QGIS на компьютере пользователя и локальный Python-плагин `water_regime_gis_plugin`; прежняя web/desktop-панель остается legacy/fallback до отдельного удаления.

## Слои архитектуры

1. **Data layer** — локальные файлы GeoTIFF, GeoPackage, CSV, Parquet; в будущем PostGIS.
2. **Processing layer** — Python, PyQGIS, GDAL/OGR, QGIS Processing, Rasterio/GeoPandas при необходимости.
3. **Analysis layer** — расчет спектральных индексов, рельефных производных и сравнительных таблиц.
4. **Application layer** — личный QGIS-плагин, запускающий проверки, выбор поля и пайплайны из интерфейса QGIS.
5. **Visualization layer** — слои, растры, preview и QGIS-проект, загружаемые прямо в текущую сессию QGIS.
6. **Knowledge layer** — `docs/wiki/` как человеко- и AI-читаемая документация.

## Текущая структура

```text
src/                  # будущий Python-пакет проекта
scripts/              # запускаемые скрипты обработки
scripts/qgis/         # скрипты, рассчитанные на запуск в QGIS Python
qgis_plugins/         # локальные QGIS-плагины проекта
notebooks/            # исследовательские ноутбуки
configs/              # конфигурации пайплайнов
data/aoi/             # границы областей интереса
data/raw/             # сырые данные
data/interim/         # промежуточные результаты
data/processed/       # обработанные результаты
outputs/maps/         # карты и QGIS-выгрузки
outputs/reports/      # отчеты
outputs/rasters/      # итоговые растры
docs/wiki/            # проектная wiki
```

## Минимальная реализация первого этапа

- `pyproject.toml` фиксирует имя проекта и минимальную версию Python.
- `configs/project.example.json` хранит базовые пути, источники данных, список индексов и DEM-продуктов.
- `src/water_regime_gis/project.py` содержит минимальные функции для поиска корня проекта, чтения JSON-конфига и проверки структуры.
- `scripts/check_project.py` является первым исполняемым скриптом проекта.
- `qgis_plugins/water_regime_gis_plugin/` является основным личным QGIS-интерфейсом.
- `src/water_regime_gis/webapp.py` сохранен как legacy/fallback интерфейс до отдельного удаления.
- `src/water_regime_gis/qgis_runtime.py` централизует поиск QGIS Python, prefix и профиля плагинов для macOS, Windows и Linux/Docker.
- `scripts/run_app.py` запускает локальное веб-приложение из рабочей копии.
- `scripts/qgis/check_qgis_context.py` проверяет запуск PyQGIS через QGIS Python.
- `scripts/install_nspd_plugin.py` автоматически устанавливает кадастровый QGIS-плагин НСПД в профиль пользователя.
- `scripts/check_satellite_pipeline.py` проверяет конфигурацию спутникового STAC/индекс-пайплайна.
- `scripts/qgis/process_satellite_indices.py` внутри QGIS Python ищет Sentinel-2 L2A сцену, обрезает каналы через GDAL и рассчитывает спектральные индексы.
- `scripts/qgis/create_demo_project.py` скрыто создает QGIS-проект `outputs/maps/water_regime_gis.qgs` и preview для панели.

## QGIS-плагин

Основной пользовательский сценарий выполняется из QGIS-плагина `Water Regime GIS`. Плагин жестко рассчитан на личную macOS-среду:

- репозиторий: `/Users/korneev/Desktop/water-regime-gis`;
- QGIS: `/Applications/QGIS.app`;
- профиль плагинов: `~/Library/Application Support/QGIS/QGIS3/profiles/default/python/plugins`.

Плагин добавляет пункт меню и toolbar action `Water Regime GIS`, открывающий dock-панель. В панели доступны действия:

- `Проверить среду`;
- `Взять точку с карты`;
- `Уточнить границу`;
- `Рассчитать индексы`;
- `Собрать проект/слои`.

Долгие операции запускаются как `QgsTask`, внутри которого вызываются существующие QGIS Python-скрипты проекта. Это сохраняет текущую проверенную логику и не блокирует интерфейс QGIS.

Установка локального плагина:

```bash
python3 scripts/install_qgis_plugin.py
```

Проверка структуры плагина:

```bash
python3 scripts/check_qgis_plugin.py
```

## Legacy desktop-приложение

Прежняя desktop/web-панель больше не является основным направлением разработки. Она остается в кодовой базе как запасной запуск и источник уже реализованных HTTP-сценариев до отдельного удаления после стабилизации QGIS-плагина.

Пробный `tkinter`-модуль `src/water_regime_gis/app.py` оставлен как черновик, но основной запуск идет через `src/water_regime_gis/webapp.py`.

Для Docker-запуска добавлены `Dockerfile` и `docker-compose.yml`. Контейнерный вариант основан на официальном `qgis/qgis:3.44-noble` и публикует ту же панель на `127.0.0.1:8765`; локальные папки `data/`, `outputs/` и `configs/` подключаются как volumes.

## PostGIS

PostGIS планируется как будущий слой хранения и пространственных запросов. На первом этапе проект должен работать без базы данных, используя файловые форматы.

## QGIS

QGIS используется как основной интерфейс и исполняемый слой для:

- запуска PyQGIS/Processing-алгоритмов;
- запуска GDAL/OGR из QGIS runtime для Sentinel-2 COG, обрезки по AOI и расчета GeoTIFF индексов;
- создания и открытия QGIS-проектов;
- подготовки preview, карт и промежуточных геоданных;
- работы с QGIS-плагинами, если их можно установить и запускать автоматически.

Пользовательские проверки и результаты должны отображаться в dock-панели плагина и загружаться в текущий QGIS-проект.

Панель дополнительно держит endpoint `/environment.json` для машинной диагностики среды: режим запуска `local`/`docker`, QGIS, скрытый PyQGIS-wrapper, НСПД-плагин и наличие готовых артефактов. Пользователь видит это как простой блок `Среда`, без необходимости понимать пути и внутренние команды.
Если QGIS не найден, панель отдает официальный URL загрузки QGIS и платформенную подсказку установки; после установки QGIS все плагины и операции остаются ответственностью приложения.

Endpoint `/readiness.json` отделяет диагностику среды от разрешения пользовательских действий. Панель и будущая desktop-оболочка должны использовать его, чтобы не запускать заведомо невозможные QGIS-сценарии.

Клиентская часть панели периодически обновляет статус системы, локальную среду и readiness. Кнопки, зависящие от QGIS и выбранного поля, должны включаться и выключаться без перезагрузки страницы.

## Автоматизация

Автоматизированные пайплайны должны быть доступны как Python-скрипты в `scripts/` и переиспользуемый код в `src/`.

Фоновые действия панели запускаются через `/job/start` и отслеживаются через `/job/status`. Job API хранит список шагов обработки и текущий шаг, чтобы интерфейс мог показывать скрытую работу QGIS без открытия QGIS пользователем.

Все скрытые subprocess-команды, включая PyQGIS-скрипты, запускаются через общий `run_command` с таймаутом. Это удерживает панель управляемой даже при зависании QGIS или внешних геосервисов.
