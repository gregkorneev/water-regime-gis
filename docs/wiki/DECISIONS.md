# Decisions

## 2026-08-13 — QGIS является единственным интерфейсом

Система работает как личный QGIS-плагин на macOS с жесткими путями. Legacy web/desktop, Docker, Windows packaging, release-сборка и HTTP API удалены.

## 2026-08-13 — Файловое хранение

AOI, промежуточные данные и результаты хранятся локально в `data/` и `outputs/` и не коммитятся. PostGIS не требуется до появления реальной необходимости.

## 2026-08-13 — Динамическая расчетная CRS

GeoJSON хранится в `EPSG:4326`, а метрические операции выполняются в локальной UTM-зоне, записанной как `analysis_crs`.

## 2026-08-13 — Sentinel-2 через Planetary Computer

Постоянные индексные GeoTIFF создает воспроизводимый PyQGIS/GDAL-пайплайн. Observearth применяется для интерактивного поиска и независимой сверки.

## 2026-08-13 — Isoliner через Processing

Используются `isoliner:raster_to_isolines` и `isoliner:kriging2d`. Кригинг не запускается без реальных точек и числового поля измерения.

## 2026-08-13 — Текущий проект сохраняется напрямую

`Собрать проект/слои` не создает отдельную скрытую сессию. Команда добавляет отсутствующие AOI/растры без дублей и сохраняет открытую сессию QGIS.

## 2026-08-13 — Метрики сохраняются отдельным JSON

Каждый расчет Sentinel-2 записывает `outputs/reports/latest_metrics.json`. Отчет содержит сведения о сцене и описательную статистику всех рассчитанных индексов.

## 2026-08-14 — Снимки KAA/SP загружаются по одному полю

Для `KAA.gpkg` и `SP.gpkg` создается отдельный RGB GeoTIFF на каждый объект и дату в диапазоне 2026-04-01–2026-08-10. На календарный день выбирается одна наименее облачная сцена. Это исключает скачивание больших пустых прямоугольников между полями и позволяет безопасно продолжать прерванную обработку.

## 2026-08-15 — Аналитические каналы привязаны к уже выбранным сценам

Для массовых расчетов индексов повторный поиск сцен не выполняется. По `scene_id` из metadata докачиваются B02/B03/B04/B05/B08/B11/B12/SCL, сохраняемые на общей сетке 10 м рядом с RGB. Облачная маска строится по SCL, а исходные RGB остаются неизменными.

## 2026-08-15 — Зональные средние KAA считаются по готовым обрезанным растрам

Для KAA не создается новый векторный пайплайн зональной статистики: каждое `sentinel_analysis.tif` уже обрезано по одному полю. Среднее берется по валидным пикселям этого растрового пятна с исключением `cloud_mask.tif`.

## 2026-08-15 — Ground-модели не запускаются без реальных наземных измерений

Табличный analysis-пайплайн готовит wide-спутниковые данные, QA и структуру M1–M4, но не генерирует синтетические `soil_moisture`, `LAI`, `FCOVER` или `OPTRAM`. Без `data/ground_measurements.csv` модели записываются как `skipped`, а OPTRAM только проверяет наличие необходимых спектральных каналов.

## 2026-08-16 — Графики индексов открываются внутри QGIS

Интерактивный просмотр временных рядов реализован в личном QGIS-плагине, а не отдельным web/desktop-приложением. Источник данных — локальная long-таблица `outputs/reports/field_zonal_means.csv`; поле выбирается по KAA/SP-полигону и нормализованному `field_id`.

## 2026-08-16 — Индексные кривые имеют единую сезонную форму

Для интерактивного графика NDVI/NDMI/NDRE/SAVI используется одна восьмипараметрическая мультипликативная double-logistic формула. Значения нормализуются в собственный диапазон, параметры подбираются отдельно для каждого `field_id + index`, но тип функции не меняется. Два параметра описывают необязательную почти горизонтальную начальную полку; штраф за ее длину оставляет полку только при улучшении fit. Произведение логистик дает один максимум и не допускает снижения до него или повторного роста после него. Fallback на сплайн или другую функцию запрещен.

Качество каждой аппроксимации показывается как `Qrob` в легенде. Метрика сравнивает ограниченную среднюю абсолютную ошибку модели с ошибкой медианного уровня; одиночные резкие провалы вниз получают пониженный вес по отношению к линейному локальному тренду. Та же система весов и robust loss `soft_l1` используются при fitting.

## 2026-08-16 — NDWI и MNDWI исключены

`NDWI` и `MNDWI` больше не рассчитываются и не показываются на интерактивных графиках. Основной набор индексов: `NDVI`, `NDMI`, `SAVI`, `NDRE`; старые локальные артефакты с удаленными индексами не удаляются автоматически.

## 2026-08-28 — Поставка КОРНИКС хранится как воспроизводимый вход

По явному решению пользователя полная поставка рядов КОРНИКС по SP за
2026-04-01—2026-08-27 перенесена из корня `Desktop/` в
`data/interim/kornix_timeseries/` и зафиксирована в git несмотря на обычное
исключение тяжёлых данных. Рабочим источником считается каталог
`sp_satellite_timeseries_20260401_20260827_v001`; `probe` и `tar.gz` сохраняются
как предоставленные исходные копии. Объединение со Sentinel-2 производится по
нормализованному полю и дате, без усреднения разных методов водного баланса.

## 2026-08-28 — Точное объединение КОРНИКС со Sentinel-2

Для первой воспроизводимой связки используется только точное совпадение даты
и нормализованный идентификатор поля (`1.1` или `SP_1_1` → `SP:1.1`). Скрипт
`merge_kornix_sentinel.py` выбирает один явно заданный метод КОРНИКС и не
заменяет отсутствующие спутниковые наблюдения ближайшей сценой: это избегает
скрытого временного сдвига в первом анализе. Возможное окно ближайшей даты
добавляется только как отдельное согласованное правило.

## 2026-08-28 — SP-индексы рассчитаны и связаны с КОРНИКС

Существующие SP-аналитические растры обработаны тем же QGIS/GDAL расчётом
зональных средних, что и KAA: получено 5 436 строк NDVI/NDMI/NDRE/SAVI.
Точное объединение с `ivanov_n4l_meteo_soil` дало 448 поле-дата совпадений
для всех 37 полей КОРНИКС. Эти строки пригодны для пилотного анализа, но не
являются доказательством корреляции без фазовой стратификации и проверки
гипотез.
