# Decisions

Журнал проектных решений.

## 2026-08-13 — Основной интерфейс переносится в личный QGIS-плагин

Решение:

- сделать QGIS основным пользовательским интерфейсом проекта;
- добавить локальный плагин `qgis_plugins/water_regime_gis_plugin/`;
- жестко закрепить личную macOS-среду: `/Applications/QGIS.app`, профиль `default`, репозиторий `/Users/korneev/Desktop/water-regime-gis`;
- установить плагин в профиль QGIS симлинком через `python3 scripts/install_qgis_plugin.py`;
- оставить прежнюю web/desktop-панель как legacy/fallback до отдельного удаления;
- запускать тяжелые операции из плагина через `QgsTask`, переиспользуя существующие QGIS Python-скрипты.

Причина:

- сервис нужен одному пользователю внутри установленного QGIS, поэтому удобнее работать прямо в QGIS и не поддерживать отдельный пользовательский web/desktop-интерфейс как основной продукт.

Ограничение:

- в v1 НСПД WMS-proxy из webapp не переносится в плагин; если локальный web-сервис не запущен, QGIS-проект использует прямой WMS/существующий request-hook и может зависеть от доступности НСПД.

## 2026-08-02 — Первый этап реализуется через минимальный проверяемый контур

Решение:

- использовать JSON как простой формат базового конфига без внешних зависимостей;

- перед публикацией проверять, что не добавлены большие геоданные или сырые пользовательские данные без разрешения.

Причина:

- GitHub-репозиторий должен всегда отражать актуальное состояние проекта.

Причина:

## 2026-08-02 — Основной интерфейс переключен на локальное веб-приложение

Решение:

- использовать `src/water_regime_gis/webapp.py` как основной интерфейс;
- запускать приложение командой `python3 scripts/run_app.py`;

- оставить пробный `tkinter`-модуль как черновой, но не использовать его для основного запуска.

Причина:

- системный Tk на macOS нестабильно отображает текст в темной теме, а локальный веб-интерфейс дает предсказуемый визуал без внешних зависимостей.

## 2026-08-02 — QGIS Python на macOS запускается через wrapper

Решение:

- использовать `/Applications/QGIS.app/Contents/MacOS/python` как основной автообнаруживаемый QGIS Python на macOS;
- не использовать напрямую `/Applications/QGIS.app/Contents/MacOS/python3.12`, потому что без wrapper не задан `PYTHONHOME`;
- исправить проверочный PyQGIS-скрипт на `Qgis.QGIS_VERSION`.

Причина:

- wrapper QGIS корректно настраивает окружение встроенного Python и позволяет импортировать `qgis.core`.

## 2026-08-09 — Основной выбор поля выполняется точкой на карте

Решение:

- убрать тестовый AOI из основного пользовательского сценария;
- добавить в локальный веб-интерфейс карту, где пользователь выбирает точку поля;
- передавать координаты точки в PyQGIS-скрипт `scripts/qgis/select_field_point.py`;
- создавать локальные слои `data/aoi/selected_field_point.geojson` и `data/aoi/selected_field_area.geojson`;
- считать эти слои пользовательскими локальными данными и не добавлять их в git;
- создавать QGIS-проект только после выбора точки поля.

Причина:

- пользователь должен сам выбирать поле, а вся геообработка выбора должна выполняться через QGIS-скрипты.

Ограничение:

- пока не подключен источник реальных границ полей, рабочая область строится как буфер вокруг выбранной точки. Этот шаг нужно заменить на выбор контура из слоя полей, когда такой слой появится.

## 2026-08-09 — Первый источник границ: Росреестр/НСПД

Решение:

- подключать кадастровые границы через QGIS-плагин `rosreestr-search-qgis-plugin`;
- добавить скрипт `scripts/qgis/check_nspd_plugin.py` для проверки наличия плагина;
- добавить в QGIS-проект WMS-слой НСПД `Земельные участки из ЕГРН`, если QGIS принимает источник;
- оставить выбранную пользователем рабочую область как временный fallback до получения векторного полигона участка.

Причина:

- пользователь выбрал первый вариант: кадастровые границы Росреестра/НСПД.

Ограничение:

- WMS-слой НСПД подходит для визуального контроля, но не заменяет векторную границу для расчетов. Следующий шаг — получить конкретный кадастровый полигон по точке или кадастровому номеру.

## 2026-08-09 — PyQGIS prefix должен оставаться на корне QGIS.app

Решение:

- запускать PyQGIS через wrapper `/Applications/QGIS.app/Contents/MacOS/python`;
- внутри скриптов задавать prefix `/Applications/QGIS.app`, если prefix нужно задать явно;
- не использовать prefix `/Applications/QGIS.app/Contents/MacOS`.

Причина:

- при prefix `/Applications/QGIS.app/Contents/MacOS` headless QGIS не загружает WMS-провайдер, и слой НСПД становится невалидным.

## 2026-08-09 — Веб-карта использует локальный прокси для НСПД WMS

Решение:

- добавить endpoint `/nspd/wms` в локальное веб-приложение;
- проксировать WMS-запросы к `nspd.gov.ru` через локальный сервер с нужным сертификатом, User-Agent и Referer;
- добавлять WMS-слой кадастровых участков НСПД в Leaflet;
- отдавать выбранную рабочую область как `/selected-field-area.geojson`;
- подсвечивать выбранную рабочую область и усиливать контур при наведении.

Причина:

- браузер не может надежно обращаться к НСПД напрямую из-за CORS/сертификатов, а WMS не дает векторную геометрию участка для hover-подсветки.

Ограничение:

- пока подсвечивается выбранная рабочая область, а не все кадастровые участки под курсором. Для этого нужен следующий шаг: векторный/identify-запрос НСПД по координате.

## 2026-08-09 — NSPD WMS proxy получает retry и короткий кеш

Решение:

- добавить один повтор WMS-запроса при временном сбое;
- кешировать WMS-ответы в памяти локального приложения на 5 минут;
- ограничить кеш 256 записями;
- добавить поддержку `HEAD /` для быстрой проверки доступности локального сервиса.

Причина:

- внешний ресурс НСПД может отвечать нестабильно, а Leaflet запрашивает несколько WMS-тайлов одновременно.

## 2026-08-09 — QGIS-проект использует локальный NSPD WMS proxy

Решение:

- для слоя `Земельные участки из ЕГРН` в QGIS-проекте использовать `http://127.0.0.1:8765/nspd/wms`;
- не сохранять в проект прямой URL `https://nspd.gov.ru/api/aeggis/v3/36048/wms`, если работает локальный сервис.

Причина:

- при прямом открытии `nspd.gov.ru` QGIS показывает SSL-диалог из-за самоподписанного корневого сертификата в цепочке. Локальный прокси уже добавляет нужный сертификат и заголовки.

Ограничение:

- перед открытием QGIS-проекта должен быть запущен локальный сервис `python3 scripts/run_app.py`.

## 2026-08-09 — QGIS-проект получает подложку и закладку выбранного поля

Решение:

- добавлять в проект `OpenStreetMap` как базовую XYZ-подложку;
- держать порядок слоев: точка, рабочая область, кадастр НСПД, OSM;
- добавлять пространственную закладку `water-regime-gis / Selected field`.

Причина:

- QGIS может открыть проект в пустом экстенте при диагностическом просмотре проекта. Закладка и подложка дают служебный возврат к выбранному участку без изменения пользовательского сценария панели.

## 2026-08-09 — Пользователь работает только через панель

Решение:

- убрать открытие QGIS и страницу плагина из основного пользовательского интерфейса;
- добавить кнопку `Проверить систему`, которая проверяет проект, устанавливает кадастровый модуль НСПД и проверяет скрытый геодвижок;
- добавить кнопку `Подготовить результат`, которая выполняет весь сценарий без ручного входа в QGIS;
- добавить `scripts/install_nspd_plugin.py` для автоматической установки `rosreestr-search-qgis-plugin`.

Причина:

- целевой пользователь не обязан знать QGIS и не должен пользоваться его интерфейсом. QGIS является внутренним движком приложения.

## 2026-08-09 — Результаты возвращаются в панель

Решение:

- после `Подготовить результат` показывать в панели блок `Результаты`;
- отдавать пользователю preview-карту, GeoJSON-контура выбранной области и JSON-отчет через download-адреса;
- сохранять краткий отчет в `outputs/reports/latest_result.json`;
- не показывать в пользовательском отчете служебный путь к внутреннему QGIS-проекту.

Причина:

- пользовательский сценарий должен завершаться внутри панели: человек получает готовые артефакты без ручного открытия QGIS и без необходимости понимать внутреннюю структуру проекта.

## 2026-08-09 — Контур поля уточняется автоматически по точке

Решение:

- добавить скрытый PyQGIS-скрипт `scripts/qgis/resolve_field_boundary.py`;
- после выбора точки и перед подготовкой результата автоматически выполнять WMS `GetFeatureInfo` к слою НСПД `Земельные участки из ЕГРН`;
- при получении полигона сохранять его в `data/aoi/selected_field_area.geojson` с `source = nspd_getfeatureinfo`;
- если НСПД недоступна или не вернула полигон, оставлять fallback-буфер с `source = map_point_buffer` и не ломать пользовательский сценарий.

Причина:

- цель панели — скрыть QGIS и технические детали. Пользователь выбирает только точку, а приложение само пытается получить наиболее точную доступную границу.

## 2026-08-09 — Панель запускает автоподготовку при старте

Решение:

- запускать bootstrap-пайплайн при старте `scripts/run_app.py`;
- выполнять проверку структуры, установку/проверку кадастрового модуля, проверку геодвижка и проверку кадастровых данных в фоновом потоке;
- показывать результат в блоке `Готовность системы`;
- отдавать машинный статус через `/status.json`;
- обновлять блок готовности в панели каждые 3 секунды;
- делать `Подготовить результат` визуально недоступной до выбора поля.

Причина:

- пользователь не должен знать, какие проверки и установки нужны перед работой. Панель должна сама приводить окружение в рабочее состояние и показывать только понятный итог.

## 2026-08-09 — macOS launcher и динамический порт панели

Решение:

- добавить `launch_panel.command` для запуска панели двойным кликом на macOS;
- при запуске пробовать порт `8765`, а если он занят, выбирать следующий свободный порт;
- передавать фактический URL панели во внутренние QGIS-скрипты через `WATER_REGIME_GIS_APP_URL`;
- использовать этот URL для локального NSPD WMS proxy в скрытых PyQGIS-скриптах.

Причина:

- пользователь не должен разбираться с терминалом и конфликтами портов. Панель должна запускаться максимально близко к обычному desktop-приложению.

## 2026-08-09 — Локальная macOS .app-оболочка

Решение:

- добавить `scripts/build_macos_app.py`;
- генерировать `dist/Water Regime GIS.app`;
- внутри bundle запускать `python3 scripts/run_app.py` из корня репозитория;
- не коммитить `dist/`.

Причина:

- `.command` уже запускает панель двойным кликом, но `.app` ближе к привычному пользовательскому формату macOS. На текущем этапе это легкая оболочка, а не полноценный standalone-дистрибутив.

## 2026-08-09 — Долгие действия панели выполняются как фоновые задачи

Решение:

- добавить `/job/start` для запуска `select-field`, `check-system` и `prepare-result`;
- добавить `/job/status` для чтения текущей или последней задачи;
- обновлять лог панели без ожидания полной загрузки страницы;
- после успешной фоновой подготовки результата один раз обновлять страницу, чтобы показать новые артефакты;
- оставить `/run/select-field`, `/run/check-system` и `/run/prepare-result` как синхронный fallback.

Причина:

- скрытые QGIS-процессы могут выполняться заметное время. Пользователь не должен воспринимать это как зависшую страницу; панель должна вести себя как обычное приложение с фоновыми задачами.

## 2026-08-09 — Фоновые задачи отдают пошаговый прогресс

Решение:

- хранить для текущей задачи `steps` и `current_step`;
- отмечать каждый скрытый QGIS-шаг как `RUNNING`, затем `OK` или `FAILED`;
- отдавать пошаговый статус через `/job/status`;
- показывать ход обработки в блоке `Лог` без ручного обновления страницы.

Причина:

- пользователь работает только через панель и должен видеть, что именно делает приложение, даже когда QGIS запускается как скрытый движок.

## 2026-08-09 — Панель показывает состояние локальной среды

Решение:

- добавить блок `Среда` в пользовательскую панель;
- показывать найденный QGIS, готовность скрытого запуска, кадастрового модуля и результатов;
- добавить `/environment.json` для машинной диагностики QGIS, НСПД-плагина и артефактов.

Причина:

- пользователь не обязан знать QGIS или терминал. Панель должна сама объяснять, готова ли локальная среда, а агенты и будущая desktop-оболочка должны получать тот же статус через API.

## 2026-08-09 — Панель блокирует невозможные действия заранее

Решение:

- добавить `/readiness.json` с флагами готовности действий;
- блокировать выбор поля, если QGIS не найден;
- блокировать подготовку результата, если QGIS не найден или поле еще не выбрано;
- показывать причину отказа в логе при прямом API-запуске.

Причина:

- пользователь не должен запускать сценарии, которые требуют знания QGIS для диагностики. Панель должна сама решать, какие действия доступны сейчас.

## 2026-08-09 — Среда и readiness обновляются без перезагрузки

Решение:

- каждые 3 секунды обновлять в панели `/status.json`, `/environment.json` и `/readiness.json`;
- перерисовывать блок `Среда`;
- включать или выключать кнопки выбора поля и подготовки результата по readiness;
- использовать делегированный обработчик кнопок, чтобы динамически созданные действия запускали фоновые задачи.

Причина:

- автоподготовка и QGIS-задачи выполняются в фоне. Панель должна сама оживать по мере готовности среды, не требуя от пользователя перезагружать страницу или понимать внутреннее состояние QGIS.

## 2026-08-09 — Скрытые команды ограничены таймаутом

Решение:

- добавить общий таймаут 180 секунд для subprocess-команд панели;
- возвращать код `124` при превышении таймаута;
