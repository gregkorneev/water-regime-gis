# `sp_zonal_means_statistics.json`: зональная статистика полей SP

## Назначение

Файл [`outputs/reports/sp_zonal_means_statistics.json`](../../outputs/reports/sp_zonal_means_statistics.json)
— переносимый экспорт результатов Sentinel-2 для полей SP. Одна запись — это
один индекс для одного поля и фактической даты съёмки. Экспорт подходит для
загрузки в другой проект, потому что не содержит абсолютных путей к локальным
растрам или QGIS-проектам.

На момент формирования файла в нём 5 935 записей: 101 поле, 1 187 пар
«поле–дата», 17 уникальных дат в интервале 2026-04-22—2026-08-20. На каждую
пару «поле–дата» приходятся пять индексов: `NDVI`, `NDMI`, `NDRE`, `SAVI` и
`FCOVER`.

## Когда наблюдение попадает в файл

Расчёт выполняется по обрезанному растровому пятну Sentinel-2 для конкретного
поля. В статистику не входят пиксели, помеченные облачной маской, тенью,
снегом, насыщением или `nodata`. Сцена целиком не используется, если доля
облаков внутри поля превышает 20%. Запись создаётся только при наличии хотя бы
одного валидного пикселя.

Это означает, что «безоблачная дата» в данном файле — дата, прошедшая два
контроля: ограничение облачности внутри границы поля и исключение невалидных
пикселей маской. Это не обязательно дата с нулевой облачностью во всей сцене
Sentinel-2.

## Структура верхнего уровня

```json
{
  "schema_version": 1,
  "generated_at": "2026-09-06T10:58:34.953074+00:00",
  "description": "Zonal statistics for cloud-filtered Sentinel-2 field patches with valid pixels.",
  "filters": {
    "cloud_mask_applied": true,
    "max_aoi_cloud_percent": 20.0,
    "invalid_pixels_excluded": true
  },
  "statistics": ["min", "max", "mean", "median"],
  "records": []
}
```

| Поле | Тип | Смысл |
| --- | --- | --- |
| `schema_version` | integer | Версия формата. В текущей поставке — `1`. При изменении структуры потребитель должен ориентироваться на это поле. |
| `generated_at` | string, ISO 8601 | Время создания файла в UTC. Это служебная метка экспорта, а не время спутниковой съёмки. |
| `description` | string | Краткое назначение набора. |
| `filters` | object | Правила отбора сцены и пикселей, применённые при расчёте. |
| `statistics` | array of string | Набор статистик, присутствующий в каждой записи. |
| `records` | array of object | Собственно зональные статистики в длинном формате. |

### Объект `filters`

| Поле | Тип | Смысл |
| --- | --- | --- |
| `cloud_mask_applied` | boolean | `true`, если применена маска недопустимых SCL-пикселей. |
| `max_aoi_cloud_percent` | number | Предельная доля облаков внутри границы поля, в процентах. В текущей поставке — `20.0`. |
| `invalid_pixels_excluded` | boolean | Подтверждает, что `nodata` и иные невалидные значения не участвовали в статистиках. |

## Формат записи

```json
{
  "dataset": "sp",
  "field_id": "SP_1_1",
  "scene_date": "2026-04-22",
  "scene_id": "S2A_MSIL2A_20260422T083741_R064_T37UDA_20260422T123509",
  "index": "NDVI",
  "min": 0.042306240648031235,
  "max": 0.17085331678390503,
  "mean": 0.06668698042631149,
  "median": 0.065561942756176,
  "valid_pixel_count": 7953,
  "invalid_pixel_count": 2863,
  "aoi_cloud_cover_percent": 0.0
}
```

| Поле | Тип | Смысл |
| --- | --- | --- |
| `dataset` | string | Набор полей. Для этого файла всегда `sp`. |
| `field_id` | string | Стабильный идентификатор поля, например `SP_1_1`. Вместе с `scene_date` и `index` образует ключ записи. |
| `scene_date` | string, `YYYY-MM-DD` | Фактическая дата наблюдения Sentinel-2. Не является интерполированной или сдвинутой датой. |
| `scene_id` | string | Идентификатор использованной сцены Sentinel-2. Нужен для трассировки источника. |
| `index` | string | Один из `NDVI`, `NDMI`, `NDRE`, `SAVI`, `FCOVER`. |
| `min` | number | Наименьшее значение индекса среди валидных пикселей поля. |
| `max` | number | Наибольшее значение индекса среди валидных пикселей поля. |
| `mean` | number | Арифметическое среднее значений валидных пикселей. Соответствует `zonal_mean` в совместимом CSV-экспорте. |
| `median` | number | Медиана значений валидных пикселей; она менее чувствительна к локальным выбросам, чем `mean`. |
| `valid_pixel_count` | integer | Число пикселей, вошедших в расчёт всех четырёх статистик. |
| `invalid_pixel_count` | integer | Число исключённых пикселей этого растрового пятна. |
| `aoi_cloud_cover_percent` | number | Доля облаков в границе данного поля по данным обработки, в процентах. |

Для каждой записи выполняются проверки: `min ≤ median ≤ max` и `min ≤ mean ≤ max`.

## Значения индексов

`NDVI`, `NDMI`, `NDRE` и `SAVI` рассчитываются из отражательной способности
Sentinel-2, приведённой к диапазону 0–1. `FCOVER` хранит результат
SNAP-совместимой биофизической модели и обычно лежит в диапазоне 0–1. Для
спектральных индексов допустимы отрицательные значения; они не являются
ошибкой формата. В частности, это относится к `NDMI` и может относиться к
остальным индексам при особенностях поверхности или атмосферной коррекции.

Минимум и максимум описывают разброс внутри поля, а не точность продукта.
Если на поле остались отдельные неотфильтрованные аномальные пиксели, они
прежде всего повлияют на эти две статистики. Для сезонных рядов обычно стоит
использовать `mean` или `median`, сохраняя `valid_pixel_count` как проверку
достаточности выборки.

## Быстрое чтение в Python

```python
import json
from pathlib import Path

payload = json.loads(Path("sp_zonal_means_statistics.json").read_text(encoding="utf-8"))
ndvi = [
    row for row in payload["records"]
    if row["field_id"] == "SP_1_1" and row["index"] == "NDVI"
]
ndvi.sort(key=lambda row: row["scene_date"])
```

Для табличной обработки удобен длинный формат `records`: его можно загрузить
в DataFrame, GeoPackage-атрибутивную таблицу или базу данных без
предварительного разворота. Если нужен один временной ряд на поле, фильтруйте
по `field_id` и `index`; если нужен срез по дате, фильтруйте по `scene_date`
и `index`.

## Связанные файлы и воспроизводимость

Исходные зональные значения и те же дополнительные статистики доступны в
[`outputs/reports/sp_zonal_means.csv`](../../outputs/reports/sp_zonal_means.csv).
CSV сохраняет абсолютный путь к аналитическому растру и нужен существующему
QGIS-плагину; JSON предпочтительнее для переноса в другой проект.

Экспорт создаёт
[`scripts/qgis/calculate_kaa_zonal_means.py`](../../scripts/qgis/calculate_kaa_zonal_means.py).
Для повторного расчёта SP из корня репозитория:

```bash
/Applications/QGIS.app/Contents/MacOS/python scripts/qgis/calculate_kaa_zonal_means.py \
  --dataset sp --report outputs/reports/sp_zonal_means.csv
```

Команда перезапишет CSV, его служебный manifest и JSON-экспорт статистик. Она
использует доступные локальные растры и их облачные маски; отсутствие нового
набора сцен не компенсируется интерполяцией.
