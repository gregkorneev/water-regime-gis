# Architecture

## Общий принцип

Проект строится вокруг QGIS как основной пользовательской среды и Python-скриптов как воспроизводимого слоя автоматизации.

## Слои архитектуры

1. **Data layer** — локальные файлы GeoTIFF, GeoPackage, CSV, Parquet; в будущем PostGIS.
2. **Processing layer** — Python, PyQGIS, GDAL/OGR, QGIS Processing, Rasterio/GeoPandas при необходимости.
3. **Analysis layer** — расчет спектральных индексов, рельефных производных и сравнительных таблиц.
4. **Visualization layer** — QGIS-проекты, стили, карты, отчеты.
5. **Knowledge layer** — `docs/wiki/` как человеко- и AI-читаемая документация.

## Текущая структура

```text
src/                  # будущий Python-пакет проекта
scripts/              # запускаемые скрипты обработки
notebooks/            # исследовательские ноутбуки
configs/              # конфигурации пайплайнов
data/aoi/             # границы областей интереса
data/raw/             # сырые данные
data/interim/         # промежуточные результаты
data/processed/       # обработанные результаты
outputs/maps/         # карты и QGIS-выгрузки
outputs/reports/      # отчеты
outputs/rasters/      # итоговые растры
docs/wiki/            # проектная wiki
```

## Минимальная реализация первого этапа

- `pyproject.toml` фиксирует имя проекта и минимальную версию Python.
- `configs/project.example.json` хранит базовые пути, источники данных, список индексов и DEM-продуктов.
- `src/water_regime_gis/project.py` содержит минимальные функции для поиска корня проекта, чтения JSON-конфига и проверки структуры.
- `scripts/check_project.py` является первым исполняемым скриптом проекта.

## PostGIS

PostGIS планируется как будущий слой хранения и пространственных запросов. На первом этапе проект должен работать без базы данных, используя файловые форматы.

## QGIS

QGIS используется для:

- визуальной проверки результатов;
- ручной подготовки AOI;
- запуска Processing-алгоритмов;
- проектирования карт;
- возможного использования плагинов Observearth и Isoliner.

## Автоматизация

Автоматизированные пайплайны должны быть доступны как Python-скрипты в `scripts/` и переиспользуемый код в `src/`.
