# QGIS Workflow

## Роль QGIS

QGIS является основной средой визуальной проверки, картографирования и ручного контроля данных.

Desktop-приложение проекта не заменяет QGIS. Оно выступает как панель запуска проверок, пайплайнов и PyQGIS-скриптов.

## Базовый рабочий процесс

1. Выбрать точку поля на карте в приложении.
2. Сохранить выбранную точку через QGIS-скрипт.
3. Проверить наличие QGIS-плагина НСПД.
4. Создать QGIS-проект с выбранной точкой и кадастровым WMS-слоем.
5. Подключить сырые спутниковые данные из `data/raw/` или внешнего каталога.
6. Проверить CRS и пространственное совпадение слоев.
7. Запустить скрипты или Processing-модели для расчета индексов.
8. Добавить полученные GeoTIFF в QGIS.
9. Подключить DEM и производные рельефные слои.
10. Сравнить спектральные и топографические признаки.
11. Сохранить карты и отчеты в `outputs/`.

## Запуск из приложения

Первая версия приложения запускается командой:

```bash
python3 scripts/run_app.py
```

Кнопка `Run QGIS check` запускает `scripts/qgis/check_qgis_context.py` через Python-интерпретатор QGIS, указанный в `configs/project.example.json`.

Форма `Выбор поля` передает координаты точки в `scripts/qgis/select_field_point.py`. Скрипт создает точечный слой выбора и временную рабочую область вокруг точки.

Кнопка `Создать QGIS проект` создает `outputs/maps/water_regime_gis.qgs` со слоем выбранной точки и рабочей области. Кнопка `Открыть QGIS проект` открывает этот файл в QGIS.

Кнопка `Проверить плагин НСПД` запускает проверку наличия `rosreestr-search-qgis-plugin`. Этот плагин нужен для устойчивой работы со слоями Публичной кадастровой карты НСПД в QGIS.

## CRS

Для тестового AOI выбрана рабочая метрическая CRS `EPSG:32637` (WGS 84 / UTM zone 37N). Исходный GeoJSON хранится в `EPSG:4326`, как обычно для GeoJSON.

Все скрипты обязаны явно проверять CRS входных данных и перепроецировать расчетные слои в рабочую CRS перед операциями площади, расстояний, уклона и сопоставления с DEM.

Пользовательский выбор поля:

- `data/aoi/selected_field_point.geojson`;
- `data/aoi/selected_field_area.geojson`;
- исходная точка хранится в `EPSG:4326`;
- рабочая область создается в метрах через `EPSG:32637` и сохраняется обратно как GeoJSON.

Тестовый AOI `data/aoi/tula_test_field.geojson` остается примером данных и не должен использоваться как безальтернативный выбор пользователя.

## Кадастровые границы

Для первого кадастрового варианта используется НСПД/Росреестр через QGIS-плагин `rosreestr-search-qgis-plugin`.

Текущий сценарий:

- пользователь выбирает точку поля;
- приложение проверяет наличие плагина НСПД;
- QGIS-проект добавляет слой `Земельные участки из ЕГРН`, если QGIS принимает WMS-источник;
- пользователь визуально сверяет выбранную точку с кадастровыми границами.

WMS-слой является картографическим слоем, а не расчетной векторной геометрией. Для последующей обрезки спутниковых снимков и DEM нужен сохраненный полигон выбранного земельного участка.

## Стили

QGIS-стили можно хранить в будущем отдельной папке, например `qgis/styles/`, если появится устойчивая схема оформления.

## Проверка результатов

Каждый автоматический пайплайн должен иметь ручной контрольный шаг в QGIS:

- открыть входные данные;
- открыть результат;
- проверить экстент, CRS, nodata и диапазон значений;
- зафиксировать замечания в wiki или отчете.
