# AGENTS.md

Инструкции для Codex и будущих AI-агентов, работающих над проектом `water-regime-gis`.

## Главные правила

- Документация ведется на русском языке.
- Имена файлов, папок, модулей и конфигураций ведутся на английском языке.
- При изменении архитектуры, пайплайнов, структуры данных или принятых решений обязательно обновлять `docs/wiki/`.
- `docs/wiki/AGENT_CONTEXT.md` держать краткой и актуальной памятью проекта.
- Новые архитектурные и методические решения записывать в `docs/wiki/DECISIONS.md`.
- Не удалять пользовательские данные.
- Не коммитить большие геоданные, растры, сцены Sentinel/Landsat, DEM и производные тяжелые файлы без явного разрешения пользователя.
- Использовать QGIS, PyQGIS, GDAL/OGR и QGIS Processing как основную технологическую базу.
- Фиксировать команды запуска, системные зависимости и Python-зависимости в документации или конфигурациях.
- После создания коммита автоматически выполнять `git push` в удаленный репозиторий для текущей ветки, если пользователь явно не попросил не пушить.

## Работа с данными

- Сырые данные хранить в `data/raw/`, но не добавлять большие файлы в git без разрешения.
- AOI и небольшие служебные геометрии хранить в `data/aoi/`.
- Промежуточные данные хранить в `data/interim/`.
- Итоговые обработанные данные хранить в `data/processed/`.
- Карты, отчеты и производные растры складывать в `outputs/`.
- Для воспроизводимости предпочтительны GeoTIFF, GeoPackage, CSV и Parquet.

## Технологические ориентиры

- QGIS должен быть основной средой визуальной проверки.
- PyQGIS и Processing использовать для автоматизации операций QGIS.
- GDAL/OGR использовать для конвертации, перепроецирования и базовой растрово-векторной обработки.
- PostGIS учитывать в архитектуре, но не требовать на первом этапе.
- Плагины Observearth и Isoliner рассматривать как возможные компоненты рабочего процесса, но не делать их обязательными без проверки.

## Git-процесс

- После внесения и проверки изменений агент должен подготовить осмысленный коммит, если пользователь просит завершить изменение в git.
- После успешного коммита агент должен автоматически выполнить `git push` для текущей ветки.
- Если удаленная ветка еще не настроена, использовать `git push -u origin <branch>`.
- Перед коммитом и push проверять, что в индекс не попали большие геоданные или пользовательские сырые данные без явного разрешения.
- Если push невозможен из-за отсутствия remote, прав доступа или сетевой ошибки, зафиксировать это в ответе пользователю вместе с точной причиной.

## Обязательная проектная память

Перед значимыми изменениями просматривать:

- `docs/wiki/INDEX.md`
- `docs/wiki/AGENT_CONTEXT.md`
- `docs/wiki/ARCHITECTURE.md`
- `docs/wiki/DATA_MODEL.md`
- `docs/wiki/PIPELINES.md`
- `docs/wiki/DECISIONS.md`

После значимых изменений обновлять:

- `docs/wiki/AGENT_CONTEXT.md`
- соответствующую страницу wiki;
- `docs/wiki/DECISIONS.md`, если принято новое решение.

## Стиль изменений

- Начинать с простого и воспроизводимого решения.
- Не добавлять тяжелые зависимости без причины.
- Не писать сложную обработку до появления тестовых данных и согласованного AOI.
- Не ломать структуру папок без обновления wiki.
- Не удалять существующие файлы пользователя без прямого запроса.
