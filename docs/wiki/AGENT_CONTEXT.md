# Agent Context

## Текущее состояние

- Основной и единственный интерфейс: QGIS-плагин `Water Regime GIS`.
- Новый рабочий вход: кнопка `Загрузить контуры полей` принимает локальный
  полигональный слой, а `Загрузить ряды из сервиса` — прямой HTTPS URL CSV/ZIP
  с колонкой `day` или `date`. Успешная выгрузка запускает
  `refresh_field_timeseries.py`: Sentinel-2 с облачной маской, FCOVER и
  индексами, затем Sentinel-1 VV/VH и зональные CSV только для выбранных
  контуров. Шесть этапов выводятся в progress bar, новые растры добавляются в
  текущий QGIS-проект. Логика `График по полю` не изменялась.
- Личная среда: macOS, `/Applications/QGIS.app`, профиль `default`, репозиторий `/Users/korneev/Desktop/water-regime-gis`.
- Плагин установлен симлинком через `python3 scripts/install_qgis_plugin.py`.
- Observearth 1.0.2 и Isoliner 5.6.21 установлены в профиль QGIS.
- Работают выбор точки, fallback AOI, попытка уточнения НСПД, Sentinel-2 и индексы NDVI/NDMI/SAVI/NDRE.
- Каждый спутниковый расчет создает `outputs/reports/latest_metrics.json` со статистикой индексных растров.
- `scripts/qgis/download_field_imagery.py` загружает временной ряд RGB Sentinel-2 для каждого поля из `KAA.gpkg` и `SP.gpkg` за заданный диапазон дат, с manifest и возобновлением. При нескольких обработках одной сцены сначала выбирается вариант с минимальной деградацией MSI, затем с меньшей облачностью.
- Тот же скачиватель поддерживает Sentinel-1 RTC: параметры `--collection sentinel-1-rtc --asset vv vh --output-name sentinel_rtc.tif --no-cloud-filter` создают двухканальный VV/VH GeoTIFF в `outputs/imagery/sentinel1/`. При докачке SP сначала запускаются 37 полей из поставки КОРНИКС, затем остальные.
- `scripts/qgis/download_field_analysis.py` возобновляемо докачивает B02/B03/B04/B05/B08/B11/B12/SCL для сохраненных сцен KAA/SP, создает `sentinel_analysis.tif`, `cloud_mask.tif` и AOI-облачность.
- `scripts/qgis/calculate_sentinel2_fcover.py` рассчитывает SNAP-совместимый FCover для сохранённых Sentinel-2 сцен: докачивает B06/B07/B8A, получает геометрию сцены и сохраняет `sentinel_fcover.tif`. Для SP подготовлены 1 535 растров FCover (2026-04-22—2026-08-20).
- `scripts/analysis/analyze_kornix_fcover_lag.py` проверяет временной сдвиг FCover и покрытия КОРНИКС. На 433 совпадениях 37 полей максимум pooled correlation — `-12` суток (Kornix сдвигается на графике вправо); bootstrap по полям: медиана/мода `-12`, 95% интервал `-16…-10` суток. Leave-one-field-out во всех 37 случаях также выбирает `-12`, но отдельные полевые оптимумы нестабильны из-за малого числа спутниковых дат и гладкой сезонной формы.
- `scripts/analysis/compare_kornix_expected_fcover.py` отдельно сравнивает
  `satellite_fcover_expected` КОРНИКС с FCOVER Sentinel-2 в совпадающие даты
  и пишет по одному набору Pearson r, bias, MAE и RMSE для каждого поля;
  20 полей отнесены к высокому совпадению, 6 — к умеренному, 11 — к слабому.
- `scripts/analysis/compare_kornix_fcover_satellite_r2.py` рассчитывает и
  группирует поля по `R²` ожидаемого FCover КОРНИКС с FCOVER Sentinel-2 на
  точных совпадениях поле-дата: высокое совпадение при положительной связи и
  `R² >= 0.70`, низкое — в остальных случаях.
- Тот же анализ сравнивает форму внутренней фазы роста по нормированной сезонной амплитуде: FCover проходит интервалы 20–35, 35–50, 50–65 и 65–80% соответственно в 1.58, 1.59, 1.55 и 1.68 раза дольше Kornix (медианы по 37 полям). Следовательно, расхождение — не жёсткий сдвиг, а более медленное нарастание спутникового FCover относительно кривой покрытия Kornix.
- `scripts/qgis/calculate_kaa_zonal_means.py` считает зональное среднее NDVI/NDMI/NDRE/SAVI/FCOVER по каждому готовому растровому пятну KAA/SP, исключая nodata, облака и сцены с облачностью внутри поля свыше 20%; загрузчик по умолчанию принимает только Sentinel-2 сцены с глобальной облачностью до 10%.
- QGIS-плагин имеет инструмент `График по полю`: при наведении на KAA/SP-полигон показывает `field_id`, а двойной щелчок открывает временной график NDVI/NDMI/NDRE/SAVI/FCOVER из `outputs/reports/field_zonal_means.csv` или `sp_zonal_means.csv`; все ряды fit-ятся одной восьмипараметрической unimodal double-logistic формулой с необязательной начальной полкой, без fallback на сплайн, и получают устойчивую метрику `Qrob`.
- Для SP тот же QGIS-диалог показывает вторым графиком ежедневные модельные
  ряды КОРНИКС выбранного метода: покрытие, Ks, влагу 0–10 см и ET/PET, а также
  столбики осадков и поливов пропорционально воде в мм/сут; третьим
  — относительный индикатор влажности Sentinel-1 по сезонному VV, нормированный
  общей шкалой 0.153527–0.367581 для всех полей. Все три панели ограничены
  первой и последней валидными датами Sentinel-2 верхнего графика; FCOVER
  Sentinel-2 и ожидаемый FCover КОРНИКС имеют одинаковый закрепленный цвет;
  остальные серии и водные столбики получают свои неповторяющиеся цвета.
  Точки
  показывают исходные даты, линия — медиану по пяти соседним наблюдениям.
- Поле `SP 7.3` исключено из интерактивного анализа по решению
  пользователя; исходные данные сохраняются без изменений.
- Кнопка `Средний график` в QGIS при каждом нажатии строит три панели по
  среднему всех полей с рядом КОРНИКС текущего метода; исключены `SP 2.7`,
  `SP 4.3`, `SP 6.6`, `SP 6.7` и `SP 7.3`. Повторные наблюдения одного поля
  за дату сводятся медианой перед равновесным средним по полям. На средней
  панели нет покрытия, а ожидаемый FCover КОРНИКС сдвинут вправо на 12 суток
  и продлён начальным уровнем до начала графика.
  Влага КОРНИКС 0–10 см перенесена на нижнюю панель к влажности Sentinel-1.
  Спутниковые точки среднего графика соединяются напрямую, без сглаживания.
- `scripts/qgis/calculate_sentinel1_zonal_means.py` формирует
  `outputs/reports/sentinel1_zonal_means.csv`: среднее обратное рассеяние VV/VH

## Следующие функции

1. Выбор конкретного контура, если НСПД возвращает неоднозначный объект.
2. Заполнить `data/ground_measurements.csv` реальными soil moisture/LAI/FCOVER и перезапустить analysis-пайплайн.
3. DEM: уклон, экспозиция, аккумуляция стока и водосборы.
4. Временные ряды и итоговая классификация зон водного режима.

Перед изменениями читать `README.md`, `ARCHITECTURE.md`, `DATA_MODEL.md`, `PIPELINES.md` и `DECISIONS.md`.
