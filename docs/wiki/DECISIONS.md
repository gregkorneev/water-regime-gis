# Decisions

Журнал проектных решений.

## 2026-08-02 — Создан начальный каркас проекта

Решение:

- вести документацию на русском языке;
- использовать английские имена файлов и папок;
- сделать QGIS и PyQGIS основой проекта;
- на первом этапе работать без PostGIS и без наземных точек;
- хранить большие геоданные вне git без явного разрешения пользователя;
- заложить `docs/wiki/` как человеко- и AI-читаемую проектную память.

Причина:

- проект начинается с архитектуры, документации и правил, без сложной обработки данных.

## 2026-08-02 — Первый этап реализуется через минимальный проверяемый контур

Решение:

- добавить `pyproject.toml`;
- использовать JSON как простой формат базового конфига без внешних зависимостей;
- добавить `scripts/check_project.py` для проверки структуры проекта;
- не добавлять тяжелые Python-зависимости до появления тестового AOI и реальных данных.

Причина:

- проекту нужен воспроизводимый стартовый запуск без привязки к локальной установке QGIS.

## 2026-08-02 — Завершенные изменения автоматически публикуются на GitHub

Решение:

- после завершения изменений агент должен выполнить `git add`, осмысленный `git commit` и `git push`;
- не оставлять завершенную работу только локально, если пользователь явно не попросил не коммитить или не пушить;
- перед публикацией проверять, что не добавлены большие геоданные или сырые пользовательские данные без разрешения.

Причина:

- GitHub-репозиторий должен всегда отражать актуальное состояние проекта.

## 2026-08-02 — Выбран тестовый AOI в Тульской области

Решение:

- использовать `data/aoi/tula_test_field.geojson` как первый тестовый AOI;
- взять небольшой контур `landuse=farmland` из OpenStreetMap через Overpass API;
- зафиксировать `EPSG:32637` как рабочую метрическую CRS для расчетов на этом AOI;
- хранить исходный GeoJSON в `EPSG:4326`.

Причина:

- проекту нужен легкий тестовый контур поля для запуска следующих пайплайнов без добавления больших геоданных.

## 2026-08-02 — Первая версия приложения строится на tkinter и MIT

Решение:

- развивать проект как desktop-приложение для Windows и macOS;
- первую версию интерфейса сделать на Python `tkinter`;
- распространять код проекта под лицензией MIT;
- запускать QGIS/PyQGIS-скрипты из приложения через путь к QGIS Python в конфиге;
- не добавлять Qt, Electron или другие тяжелые GUI-зависимости на первом интерфейсном шаге.

Причина:

- нужен быстрый открытый кроссплатформенный интерфейс без лицензионной сложности и без преждевременной упаковки.

## 2026-08-02 — Проверка AOI реализована без внешних GIS-зависимостей

Решение:

- добавить `scripts/check_aoi.py`;
- проверять GeoJSON, тип геометрии, bbox, замкнутость полигона и примерную площадь стандартной библиотекой Python;
- добавить кнопку `Проверить AOI` в desktop-приложение;
- рабочую нормализованную копию AOI писать в `data/interim/`, не коммитя производный файл.

Причина:

- нужен первый полезный сценарий приложения без преждевременной установки GDAL/GeoPandas/PyQGIS на этапе проверки интерфейса.
