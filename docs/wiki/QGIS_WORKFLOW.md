# QGIS Workflow

## Роль QGIS

QGIS теперь является основным интерфейсом проекта. Пользователь открывает установленный QGIS, включает локальный плагин `Water Regime GIS` и запускает сценарии из dock-панели внутри QGIS.

Прежняя локальная web/desktop-панель остается legacy/fallback до отдельного удаления.

## Базовый рабочий процесс

1. Пользователь запускает `python3 scripts/install_qgis_plugin.py` один раз и перезапускает QGIS.
2. В QGIS пользователь включает плагин `Water Regime GIS`.
3. Пользователь открывает dock-панель `Water Regime GIS`.
4. Кнопка `Проверить среду` проверяет QGIS, жесткие пути, профиль плагинов и рабочие папки.
5. Кнопка `Взять точку с карты` включает выбор точки кликом по canvas QGIS.
6. Плагин запускает `scripts/qgis/select_field_point.py` и загружает созданные GeoJSON-слои в QGIS.
7. Кнопка `Уточнить границу` запускает `scripts/qgis/resolve_field_boundary.py`.
8. Кнопка `Рассчитать индексы` запускает `scripts/qgis/process_satellite_indices.py` в фоне.
9. Кнопка `Собрать проект/слои` запускает `scripts/qgis/create_demo_project.py` без legacy WMS-прокси НСПД и открывает результат в QGIS.

## Запуск из QGIS

Установка плагина в профиль QGIS `default`:

```bash
python3 scripts/install_qgis_plugin.py
```

Проверка структуры плагина:

```bash
python3 scripts/check_qgis_plugin.py
```

Плагин жестко использует:

- `/Users/korneev/Desktop/water-regime-gis`;
- `/Applications/QGIS.app`;
- `~/Library/Application Support/QGIS/QGIS3/profiles/default/python/plugins`.

Для v1 НСПД WMS-proxy из webapp не переносится в плагин. Проект, собранный из QGIS-плагина, не включает WMS-слой НСПД, чтобы QGIS не показывал диалог недоступного слоя при выключенной legacy web-панели. Кадастровый контур по-прежнему уточняется отдельным `GetFeatureInfo`-скриптом; визуальный WMS можно добавить через установленный НСПД-плагин QGIS.

## CRS

Для тестового AOI выбрана рабочая метрическая CRS `EPSG:32637` (WGS 84 / UTM zone 37N). Исходный GeoJSON хранится в `EPSG:4326`, как обычно для GeoJSON.

Все скрипты обязаны явно проверять CRS входных данных и перепроецировать расчетные слои в рабочую CRS перед операциями площади, расстояний, уклона и сопоставления с DEM.

Пользовательский выбор поля:

- `data/aoi/selected_field_point.geojson`;
- `data/aoi/selected_field_area.geojson`;
- исходная точка хранится в `EPSG:4326`;
- рабочая область создается в метрах через `EPSG:32637` и сохраняется обратно как GeoJSON.

Тестовый AOI `data/aoi/tula_test_field.geojson` остается примером данных и не должен использоваться как безальтернативный выбор пользователя.

## Кадастровые границы

Для первого кадастрового варианта используется НСПД/Росреестр через QGIS-плагин `rosreestr-search-qgis-plugin`.

Текущий сценарий:

- пользователь выбирает точку поля в панели;
- приложение автоматически устанавливает и проверяет плагин НСПД;
- скрытый PyQGIS-процесс добавляет слой `Земельные участки из ЕГРН`;
- веб-карта показывает кадастровый WMS-слой НСПД через локальный прокси;
- выбранная рабочая область подсвечивается на сайте как GeoJSON-слой;
- пользователь визуально сверяет выбранную точку с кадастровыми границами.

WMS-слой является картографическим слоем, а не расчетной векторной геометрией. Для последующей обрезки спутниковых снимков и DEM нужен сохраненный полигон выбранного земельного участка.

## Стили

QGIS-стили можно хранить в будущем отдельной папке, например `qgis/styles/`, если появится устойчивая схема оформления.

## Проверка результатов

Каждый автоматический пайплайн должен иметь контрольный шаг в панели:

- показать входные параметры;
- показать preview результата;
- проверить экстент, CRS, nodata и диапазон значений автоматически или через отчет;
- зафиксировать замечания в wiki или отчете.
