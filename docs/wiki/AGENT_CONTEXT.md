# Agent Context

Краткая актуальная память проекта для Codex и будущих AI-агентов.

## Состояние

Проект находится на первом этапе. Создан каркас репозитория, базовая wiki, `.gitignore`, правила для агентов, `pyproject.toml`, пример конфига, скрипты проверки и первый пользовательский сценарий выбора поля через карту.

## Цель

Разработать QGIS-ориентированную систему анализа водного режима сельскохозяйственных земель на основе спутниковых данных, DEM и расчетных слоев. Наземные точки будут добавлены позже.

## Текущие решения

- Документация ведется на русском языке.
- Имена файлов и папок — на английском.
- Основной стек: macOS, QGIS, PyQGIS, QGIS Processing, GDAL/OGR, Python.
- Основной пользовательский сценарий переключен на личный QGIS-плагин `Water Regime GIS`; QGIS больше не считается скрытым только движком.
- Плагин расположен в `qgis_plugins/water_regime_gis_plugin/` и устанавливается командой `python3 scripts/install_qgis_plugin.py`.
- Плагин жестко использует `/Users/korneev/Desktop/water-regime-gis`, `/Applications/QGIS.app` и профиль QGIS `default`.
- Проверка структуры плагина: `python3 scripts/check_qgis_plugin.py`.
- Прежняя web/desktop-панель остается legacy/fallback до отдельного удаления после стабилизации QGIS-плагина.
- PostGIS планируется, но не требуется на первом этапе.
- Большие геоданные не добавляются в git без явного разрешения.
- `docs/wiki/DECISIONS.md` является журналом решений.
- Все завершенные изменения должны автоматически коммититься и пушиться на GitHub, если пользователь явно не попросил обратное.
- Первый исполняемый скрипт: `python3 scripts/check_project.py`.
- Базовый конфиг: `configs/project.example.json`.
- Тестовый AOI `data/aoi/tula_test_field.geojson` остается примером данных, но основной пользовательский сценарий больше не привязан к нему.
- В новом основном сценарии пользователь выбирает поле кликом по canvas QGIS через плагин; legacy web-панель тоже умеет выбирать точку на карте.
- Выбор точки обрабатывается QGIS-скриптом `scripts/qgis/select_field_point.py`.
- Новый пользовательский сценарий выполняется в QGIS: плагин открывает dock-панель, берет точку кликом по canvas, запускает существующие QGIS-скрипты в фоне и загружает результаты в QGIS.
- Основные кнопки QGIS-плагина: `Проверить среду`, `Взять точку с карты`, `Уточнить границу`, `Рассчитать индексы`, `Собрать проект/слои`.
- Legacy web-панель сохраняет прежние кнопки `Сохранить выбранное поле`, `Восстановить среду`, `Проверить систему`, `Подготовить результат` до отдельного удаления.
- QGIS-плагин загружает результаты в текущую сессию QGIS; legacy web-панель после подготовки результата показывает блок `Результаты` со скачиванием единого ZIP-архива, preview, GeoJSON-контура и JSON-отчета `outputs/reports/latest_result.json`.
- НСПД-плагин автоматически устанавливается скриптом `scripts/install_nspd_plugin.py`.
- Скрипт создает локальные некоммитимые слои `data/aoi/selected_field_point.geojson` и `data/aoi/selected_field_area.geojson`.
- Скрипт `scripts/qgis/resolve_field_boundary.py` автоматически пытается уточнить реальный кадастровый контур через WMS `GetFeatureInfo` НСПД по выбранной точке.
- Если НСПД недоступна, не возвращает полигон или возвращает слишком крупный кадастровый объект, граница поля моделируется fallback-буфером вокруг выбранной точки.
- Первый выбранный источник реальных границ: Росреестр/НСПД через QGIS-плагин `rosreestr-search-qgis-plugin`.
- Добавлен QGIS-скрипт проверки плагина: `scripts/qgis/check_nspd_plugin.py`.
- На macOS 2026-08-09 плагин НСПД установлен в профиль QGIS `default`.
- Панель читает `metadata.txt` НСПД-плагина и показывает версию модуля в блоке `Среда`.
- Установщик и QGIS-check считают НСПД-плагин готовым только если `metadata.txt` содержит ожидаемое имя `rosreestr-search-qgis-plugin`; поврежденный metadata запускает переустановку.
- Проект, собранный из QGIS-плагина, не сохраняет legacy WMS-слой НСПД: его локальный proxy зависит от выключенной web-панели и вызывает диалог недоступного слоя. Визуальный кадастровый WMS добавляется отдельно через НСПД-плагин QGIS.
- Веб-карта добавляет кадастровый WMS-слой через локальный прокси `/nspd/wms`.
- Веб-карта имеет только три базовых режима `Карта`, `Спутник`, `Гибрид`; `Карта` использует растровую OpenStreetMap с локальными названиями и дополнительными русскими подписями стран/регионов на малых масштабах, `Гибрид` использует Esri World Imagery и единственный слой подписей OpenFreeMap/OpenMapTiles с приоритетом `name:ru`, свежий Sentinel-2 автоматически встраивается в два спутниковых режима, а кадастровый WMS НСПД включается/выключается отдельным overlay-чекбоксом.
- При наличии подготовленного Sentinel-2 карта по умолчанию открывается в режиме `Гибрид`.
- Гибридный режим содержит спутниковую Esri World Imagery и только символьные слои OpenFreeMap; англоязычные reference-слои Esri не используются, чтобы не дублировать подписи.
- Для всех режимов используется один экземпляр MapLibre-слоя: он показывает только страны/регионы в `Карта`, полный набор обозначений в `Гибрид` и визуально скрывается в `Спутник` без уничтожения WebGL-контекста.
- Веб-карта поддерживает `lat`, `lon`, `zoom` в URL для проверки вида без сохранения поля.
- Прокси `/nspd/wms` использует один retry и in-memory кеш на 5 минут для стабильности карты.
- Legacy web-сценарий может использовать локальный WMS-прокси `http://127.0.0.1:8765/nspd/wms`; QGIS-plugin workflow его не записывает в проект.
- QGIS-проект добавляет OpenStreetMap-подложку и закладку `water-regime-gis / Selected field` для возврата к выбранной области.
- Выбранная рабочая область отдается как `/selected-field-area.geojson` и подсвечивается при наведении.
- Подсветка всех кадастровых участков при наведении пока не реализована: WMS является картинкой, нужен векторный/identify-запрос НСПД.
- Рабочая CRS для выбранного поля выбирается динамически как локальная UTM-зона по выбранной точке, например `EPSG:32637` для Тульской области и `EPSG:32646` для района 91°E.
- Проект теперь развивается как desktop-приложение для Windows и macOS.
- Первая версия GUI: `python3 scripts/run_app.py`, локальный веб-интерфейс `http://127.0.0.1:8765` на стандартной библиотеке Python.

- E2E-проверка сохраняет и восстанавливает локальные выбранные поля, preview, QGIS-проект и JSON-отчет.
- Сгенерированная папка `dist/` игнорируется git и не коммитится.
- Если порт `8765` занят, панель автоматически выбирает следующий свободный порт.
- Текущий URL панели передается скрытым QGIS-скриптам через `WATER_REGIME_GIS_APP_URL`.
- При старте панели автоматически запускается bootstrap: проверка структуры, автоустановка НСПД-плагина, проверка PyQGIS и проверка кадастрового модуля.
- Блок `Готовность системы` показывает пользователю статус bootstrap без необходимости открывать QGIS или читать терминал.
- Блок `Среда` показывает режим запуска (`Локальный запуск` или `Docker-контейнер`), найденный QGIS, скрытый запуск, кадастровый модуль и наличие результатов без технических деталей.
- Если QGIS не найден, блок `Среда` показывает кнопку `Скачать QGIS` и платформенную подсказку установки через `qgis_runtime.qgis_install_hint`.
- `/status.json` отдает машинный статус bootstrap для будущего desktop-shell или агентов.
- `/environment.json` отдает машинную диагностику режима запуска, QGIS, НСПД-плагина и пользовательских артефактов для будущего desktop-shell или агентов.
- `/readiness.json` отдает готовность действий панели: можно ли выбрать поле и можно ли подготовить результат.
- Веб-панель каждые 3 секунды опрашивает `/status.json`, `/environment.json` и `/readiness.json`, обновляя готовность, среду и доступность действий без перезагрузки страницы.
- `Подготовить результат` визуально недоступен до выбора точки поля.
- Действия выбора поля и подготовки результата блокируются заранее, если QGIS не найден или поле еще не выбрано.
- `Сохранить выбранное поле`, `Проверить систему` и `Подготовить результат` в обычном UI запускаются как фоновые задачи через `/job/start`; лог читается через `/job/status`.
- Обработчики кнопок действий регистрируются отдельным ранним скриптом до загрузки Leaflet/MapLibre, чтобы действия панели работали даже при сбое внешних картографических CDN.
- `Восстановить среду` запускает тот же скрытый workflow автоустановки/проверки, что и системная проверка, но как явное пользовательское действие восстановления.
- `/job/status` возвращает `steps` и `current_step`, поэтому панель показывает ход скрытых QGIS-операций по шагам, а не только финальный лог.
- Скрытые системные и QGIS-команды имеют таймаут 180 секунд; при зависании панель возвращает понятное сообщение вместо бесконечного ожидания.
- `/run/select-field`, `/run/check-system` и `/run/prepare-result` сохранены как синхронный fallback.
- Код проекта распространяется под MIT; сведения о сторонних лицензиях в `THIRD_PARTY_NOTICES.md`.
- QGIS найден на macOS в `/Applications/QGIS.app`; для PyQGIS использовать wrapper `/Applications/QGIS.app/Contents/MacOS/python`.
- Если в конфиге указан `qgis.python_executable`, панель считает QGIS найденным только при существующем файле по этому пути.
- Внутри PyQGIS-скриптов использовать prefix `/Applications/QGIS.app`; prefix `/Applications/QGIS.app/Contents/MacOS` ломает загрузку WMS-провайдера.
- QGIS-проект и preview создаются скрыто из панели через `/run/prepare-result`.
- Выходной проект: `outputs/maps/water_regime_gis.qgs`.

## Следующий практический шаг

Добавить пользовательский выбор конкретного кадастрового контура, если НСПД возвращает несколько участков или слишком крупный объект вместо сельскохозяйственного поля.
