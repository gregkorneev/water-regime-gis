# App

## Назначение

Проект развивается как desktop-приложение для Windows и macOS. Пользователь работает только с панелью приложения; QGIS используется как скрытый геодвижок и не является пользовательским интерфейсом.

## Текущая первая версия

Текущая первая версия реализована как локальное веб-приложение на стандартной библиотеке Python:

- файл приложения: `src/water_regime_gis/webapp.py`;
- запуск из репозитория: `python3 scripts/run_app.py`;
- Docker-запуск: `docker compose up --build`;
- Windows launcher: `launch_panel.bat`;
- адрес: `http://127.0.0.1:8765`;
- проверка HTML-интерфейса без открытия браузера: `python3 scripts/check_app.py`;
- первый QGIS-скрипт: `scripts/qgis/check_qgis_context.py`;
- выбор поля точкой на карте: `scripts/qgis/select_field_point.py`;
- автоустановка кадастрового модуля: `scripts/install_nspd_plugin.py`;
- подготовка результата: кнопка `Подготовить результат`.

Ранее была пробная `tkinter`-версия в `src/water_regime_gis/app.py`, но на macOS системный Tk оказался нестабильным по отображению темной темы. Основной запуск переключен на локальный веб-интерфейс.

## Почему локальный веб-интерфейс

Локальный веб-интерфейс работает на Windows и macOS через браузер, не требует внешних GUI-зависимостей и сохраняет открытую лицензионную модель. В будущем его можно упаковать в `.app`/`.exe` с локальным сервером или заменить на нативную оболочку.

## Скрытый геодвижок

Приложение само запускает QGIS/PyQGIS-скрипты через путь `qgis.python_executable` из `configs/project.example.json` или через автообнаружение `src/water_regime_gis/qgis_runtime.py`. Пользователь не должен открывать QGIS, устанавливать плагины вручную или пользоваться интерфейсом QGIS.

На macOS приложение пробует найти `/Applications/QGIS.app/Contents/MacOS/python`. На Windows проверяются типовые `python-qgis.bat` в `C:\Program Files\QGIS*` и `C:\OSGeo4W`. В Docker используется официальный образ `qgis/qgis:3.44-noble`, где PyQGIS доступен через системный `python3`.

Внутри PyQGIS-скриптов prefix задается через `qgis_runtime.py`: `/Applications/QGIS.app` на macOS, `C:\Program Files\QGIS*`/OSGeo4W на Windows или `/usr` в Linux/Docker. Prefix `/Applications/QGIS.app/Contents/MacOS` на macOS не подходит для WMS-слоев, потому что QGIS тогда не видит WMS-провайдер.

Если QGIS не найден, панель показывает платформенную подсказку: macOS — установка в `/Applications/QGIS.app`, Windows — установка QGIS или OSGeo4W, Linux/Docker — установка QGIS/PyQGIS или запуск Docker-варианта.

Запуск на macOS для пользователя:

```text
launch_panel.command
```

Файл можно открыть двойным кликом из Finder. Запасной запуск из терминала:

```bash
python3 scripts/run_app.py
```

Запуск на Windows для пользователя:

```text
launch_panel.bat
```

Docker-запуск:

```text
launch_docker.command
```

На Windows:

```text
launch_docker.bat
```

Запасной запуск Docker из терминала:

```bash
docker compose up --build
```

Docker launchers проверяют наличие Docker, поднимают `docker compose up --build -d` и открывают `http://127.0.0.1:8765`. Docker-вариант слушает `0.0.0.0:8765` внутри контейнера и публикует панель как `http://127.0.0.1:8765`. Образ основан на `qgis/qgis:3.44-noble`; пользовательские `data/` и `outputs/` остаются на хосте через volume.

Docker-вариант проверяется командой `python3 scripts/check_docker_app.py`: она собирает образ, запускает контейнерную панель на свободном локальном порту, ждет автоподготовку и проверяет, что внутри доступны QGIS 3.40+ и НСПД-плагин. Для Linux/Docker `qgis_runtime.py` выставляет `QT_QPA_PLATFORM=offscreen`, чтобы PyQGIS работал без графического дисплея.

Панель показывает режим запуска в блоке `Среда`: `Локальный запуск`, если используется QGIS с компьютера пользователя, или `Docker-контейнер`, если приложение работает внутри контейнера. Машинно это доступно в `/environment.json` как `runtime.mode`.

Сборка пользовательского Docker-first пакета:

```bash
python3 scripts/build_release_package.py
```

Скрипт создает `dist/water-regime-gis-release/`. Это переносимый пакет без необходимости запускать проект из репозитория:

- `Water Regime GIS.app` — macOS launcher;
- `Water Regime GIS.command` — запасной macOS launcher;
- `Water Regime GIS.bat` — Windows launcher;
- `docker-compose.yml` — запуск контейнерной панели;
- `water-regime-gis-image.tar` — сохраненный Docker-образ с кодом проекта и QGIS runtime;
- `data/`, `outputs/`, `configs/` — пользовательские данные, результаты и конфигурация рядом с приложением.

При первом запуске launcher проверяет Docker Desktop, загружает `water-regime-gis-image.tar` как image `water-regime-gis:release`, запускает `docker compose up -d` и открывает `http://127.0.0.1:8765`. QGIS находится внутри Docker-образа и не открывается пользователем.

Собранный пакет проверяется командой `python3 scripts/check_release_package.py`.

Повторная сборка release-пакета обновляет launchers, compose и Docker image tar, но не удаляет пользовательские папки `data/`, `outputs/` и `configs/` внутри `dist/water-regime-gis-release/`.

Сборка локального `.app`:

```bash
python3 scripts/build_macos_app.py
```

Скрипт создает `dist/Water Regime GIS.app`. Приложение является легкой оболочкой над текущим репозиторием: при запуске оно переходит в корень проекта и вызывает `python3 scripts/run_app.py`.

Панель старается занять `http://127.0.0.1:8765`. Если порт занят, приложение автоматически выбирает следующий свободный порт и передает этот адрес скрытым QGIS-скриптам через `WATER_REGIME_GIS_APP_URL`.

При старте приложение запускает фоновую автоподготовку:

- проверяет структуру проекта;
- устанавливает или проверяет кадастровый модуль НСПД;
- проверяет доступность скрытого геодвижка;
- проверяет доступность кадастровых данных.

Результат автоподготовки отображается в блоке `Готовность системы` и доступен как JSON через `/status.json`.
Панель опрашивает `/status.json` каждые 3 секунды и обновляет блок готовности без перезагрузки страницы.

Затем в интерфейсе:

- `Сохранить выбранное поле` — передает координаты выбранной на карте точки в скрытый PyQGIS-скрипт через фоновую задачу;
- `Проверить систему` — проверяет структуру проекта, устанавливает/проверяет кадастровый модуль НСПД и проверяет доступность геодвижка;
- `Подготовить результат` — выполняет весь сценарий: проверка, автоустановка кадастрового модуля, запуск PyQGIS, создание QGIS-проекта и preview для панели.

`Сохранить выбранное поле`, `Проверить систему` и `Подготовить результат` запускают задачи в фоне через `/job/start`. Панель опрашивает `/job/status`, обновляет лог без ожидания загрузки страницы и после успешного выбора поля или подготовки результата обновляет экран, чтобы показать новые данные.

До выбора точки поля кнопка `Подготовить результат` показана как недоступная. Это защищает пользователя от запуска пайплайна без входных координат.

Кнопки открытия QGIS и страницы плагина убраны из пользовательского сценария.

## Результаты в панели

После успешного запуска `Подготовить результат` панель показывает блок `Результаты`.

В нем доступны:

- единый ZIP-архив результата через `/download/result.zip`;
- скачивание preview-карты через `/download/preview.png`;
- скачивание GeoJSON-контура выбранной области через `/download/field.geojson`;
- скачивание JSON-отчета через `/download/report.json`.

JSON-отчет сохраняется в `outputs/reports/latest_result.json`. Он содержит статус подготовки, время, параметры выбранного поля, ссылки на пользовательские артефакты и очищенный лог без служебных путей к внутреннему проекту.

## Выбор поля

Основной вход пользователя на первом этапе — точка на карте. Приложение не подставляет заранее выбранное тестовое поле как рабочую область.

После клика по карте пользователь сохраняет выбранное поле. Внутренний PyQGIS-скрипт создает:

- `data/aoi/selected_field_point.geojson` — точка выбора в `EPSG:4326`;
- `data/aoi/selected_field_area.geojson` — временная рабочая область вокруг точки.

После этого панель автоматически запускает `scripts/qgis/resolve_field_boundary.py`. Скрипт через скрытый PyQGIS-процесс делает `GetFeatureInfo` к кадастровому WMS НСПД по выбранной точке. Если НСПД возвращает полигон, `selected_field_area.geojson` заменяется реальным кадастровым контуром. Если НСПД недоступна или не возвращает полигон, остается временная рабочая область вокруг точки.

Эти файлы считаются локальным пользовательским выбором и не добавляются в git.

Веб-карта отображает:

- русскоязычную векторную подложку OpenFreeMap/OpenMapTiles на данных OpenStreetMap;
- спутниковую подложку Esri World Imagery;
- гибридный режим со спутниковой подложкой и русскими подписями;
- последнюю рассчитанную Sentinel-2 true-color подложку по выбранному полю, если спутниковый пайплайн уже выполнялся;
- кадастровый WMS-слой НСПД через локальный прокси `/nspd/wms`;
- выбранную рабочую область как векторный GeoJSON `/selected-field-area.geojson`.

Переключатель слоев карты всегда содержит только три базовых режима: `Карта`, `Спутник` и `Гибрид`. Подписи в режимах `Карта` и `Гибрид` берутся из поля `name:ru` OpenMapTiles с fallback на основное имя объекта. Если спутниковый пайплайн уже выполнялся, свежий Sentinel-2 для выбранного поля автоматически показывается внутри режимов `Спутник` и `Гибрид`, не создавая дополнительные пункты. Кадастровый слой НСПД включается и выключается отдельным чекбоксом.

Выбранная область подсвечивается отдельным цветом, а при наведении на нее контур усиливается. Подсветка всех соседних кадастровых участков при наведении требует отдельного векторного/identify-запроса НСПД для каждого объекта, потому что WMS сам по себе является картинкой.

Прокси `/nspd/wms` делает один повтор при временном сбое НСПД и держит небольшой in-memory кеш WMS-ответов на 5 минут. Это снижает дергание карты при повторной загрузке тех же тайлов.

QGIS-проект тоже использует локальный WMS-прокси `http://127.0.0.1:8765/nspd/wms` для кадастрового слоя. Это убирает SSL-диалог QGIS по сертификату `nspd.gov.ru`. Перед открытием проекта QGIS локальный сервис должен быть запущен.

В QGIS-проект добавляется базовая подложка `OpenStreetMap`, кадастровый WMS-слой НСПД, выбранная рабочая область и точка выбора. Также создается пространственная закладка `water-regime-gis / Selected field` для быстрого возврата к выбранному участку, если QGIS открыл проект в пустом экстенте.

## Кадастровые границы НСПД

Первый выбранный источник границ — Росреестр/НСПД через QGIS-плагин `rosreestr-search-qgis-plugin`.

Плагин:

- страница QGIS: `https://plugins.qgis.org/plugins/rosreestr-search-qgis-plugin-master/`;
- назначение: поиск по Публичной кадастровой карте НСПД и загрузка слоев НСПД;
- актуальная проверенная по каталогу QGIS версия на 2026-08-09: 2.5;
- минимальная версия QGIS для 2.5: 3.40.

Скрипт `scripts/install_nspd_plugin.py` автоматически скачивает и устанавливает плагин в профиль QGIS, если он еще не установлен. Скрипт `scripts/qgis/check_nspd_plugin.py` проверяет наличие плагина после установки.

Скрипт `scripts/qgis/create_demo_project.py` пытается добавить WMS-слой `Земельные участки из ЕГРН` из НСПД. Без установленного плагина QGIS может пометить слой как невалидный из-за особенностей доступа к `nspd.gov.ru`.

## Упаковка

Для macOS реализована локальная `.app`-оболочка через `scripts/build_macos_app.py`. Она не встраивает Python и код проекта внутрь bundle, а запускает панель из текущего репозитория. Это промежуточный шаг к полноценной дистрибуции.

Для Windows добавлен простой `launch_panel.bat`, который запускает ту же локальную панель из репозитория.

Основной продуктовый путь упаковки — `scripts/build_release_package.py`: он создает Docker-first пакет для macOS и Windows с готовым Docker-образом приложения.

Упаковка в standalone `.app` с вендорингом зависимостей и `.exe` для Windows пока не реализована.
